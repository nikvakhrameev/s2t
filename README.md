# s2t — локальный speech-to-text для macOS (Apple Silicon)

Всё работает локально: `ffmpeg → Silero VAD → Whisper large-v3-turbo (MLX) → замена алиасов → LLM-очистка (MLX)`.
Единственное исключение — опциональная смысловая проверка результата облачной моделью
[Jev](#смысловая-проверка-jev-опционально) (TypeSafe), по умолчанию выключена.

```
любое аудио ──ffmpeg──▶ 16 kHz mono ──VAD──▶ речь без тишины ──Whisper──▶ сырой текст
                                                  │                          │
                                     нет речи → пустой ответ        glossary aliases (regex)
                                     (STT не вызывается)                     │
                                                                  LLM-очистка + guardrail ──▶ текст
                                                                     (+ Jev, опционально)
```

## Запуск

```bash
uv sync
uv run s2t serve                          # модели в памяти: HTTP API + хоткей диктовки
uv run s2t transcribe -v file.ogg         # разовая транскрибация (использует сервер, если он запущен)
curl -F file=@voice.m4a -F language=ru http://127.0.0.1:8765/transcribe
```

Первый запуск скачивает модели (~1.6 ГБ Whisper, ~2.3 ГБ LLM, 2 МБ VAD).

### Диктовка (push-to-talk)

`s2t serve` слушает глобальный хоткей: **зажать правый Option → говорить → отпустить** — текст
вставляется в активное приложение (через буфер обмена + Cmd+V, буфер затем восстанавливается).
Хоткеи и язык для каждого задаются в `config.yaml` (`dictation.hotkeys`) — можно завести отдельные
клавиши для `ru` / `en` / `auto`.

Пока клавиша зажата, поверх всех окон (включая полноэкранные) висит индикатор: пульсирующая красная
точка и таймер записи `0:07`. Он появляется в момент, когда микрофон реально начал писать, не
перехватывает фокус и клики. Положение, размер и выключатель — `dictation.overlay` в `config.yaml`.

Приложению, из которого запущен сервис (Terminal/iTerm), нужны разрешения в
System Settings → Privacy & Security: **Microphone**, **Input Monitoring**, **Accessibility**.

## Как решены требования

| Требование | Решение |
|---|---|
| RU + EN одной моделью | Whisper large-v3-turbo на MLX. `language: auto` выбирает язык только среди `auto_languages: [ru, en]` — не бывает ложных uk/bg на коротких фразах с англицизмами. |
| Тишина по краям | Silero VAD (ONNX, без torch): края обрезаются до `edge_pad_ms`. |
| Паузы внутри | Паузы длиннее `max_pause_ms` сжимаются до этого значения (заполняются исходным шумом комнаты, а не цифровым нулём — границы фраз остаются слышны). |
| Галлюцинации | 1) если VAD не нашёл речь — Whisper не вызывается; 2) `condition_on_previous_text=False`; 3) пороги no_speech / logprob / compression; 4) фильтр типовых фраз («Субтитры сделал…», «Thanks for watching») и повтора собственного промпта. |
| Лёгкая LLM-очистка | Qwen3-4B-Instruct 4-bit на MLX, greedy, системный промпт + few-shot закэшированы в KV (запрос платит только за свои токены). |
| «Не менять смысл» | Жёсткий промпт (текст — данные, не инструкция), лимит токенов от длины входа, **guardrails** на каждый чанк: ни одного выдуманного слова (каждое слово вывода должно соответствовать слову транскрипта — точно, близко по написанию (`spelling_similarity`) или через транслитерацию (`translit_similarity`, «питоне→Python»)), нельзя добавлять отрицания и терять больше `max_negation_loss` из них (по умолчанию 0.5: потеря единственного «не» отклоняется, одного из двух — допускается, т.к. при запинках отрицания повторяются), удалять можно только слова-паразиты и повторы (+≤10% прочих слов, `max_dropped_ratio`). Нарушение → повтор по предложениям → иначе возвращается сырой транскрипт. Опционально поверх эвристик (или вместо них) — смысловая проверка моделью Jev, см. ниже. |
| Словари | `glossary.yaml`, три слоя (см. ниже): термины → prompt Whisper; список терминов → в системный промпт LLM; опциональные `aliases` → детерминированная замена. Перечитывается на лету. |
| Любое аудио | ffmpeg декодирует всё (mp3, m4a, ogg/opus, webm, mp4/видео…) в 16 kHz mono f32. |

## Смысловая проверка: Jev (опционально)

Эвристики guardrail'а сравнивают слова, а не смысл. Их слепые пятна: перестановка ролей
(«Иван отправит Пете» → «Петя отправит Ивану»), порядок шагов, двойное отрицание в пределах
`max_negation_loss`, числа короче трёх символов («15:30» → «16:30»), одно выпавшее значимое слово
(«только на стейджинг»). Их закрывает [Jev](https://docs.typesafe.ai) — модель TypeSafe, которая
не генерирует текст, а отвечает на типизированные вопросы вероятностями.

```bash
mkdir -p ~/.config/s2t && pbpaste > ~/.config/s2t/typesafe_api_key && chmod 600 ~/.config/s2t/typesafe_api_key
# или: export TYPESAFE_API_KEY=…   (ключи: https://console.typesafe.ai/keys)
uv run python scripts/eval_jev.py           # калибровка: риски всех вопросов на хороших и плохих парах
```

- `mode: both` (по умолчанию) — чанк должен пройти эвристики **и** Jev. В Jev уходит только то, что
  эвристики пропустили; если изменились лишь пунктуация и регистр, запроса нет.
- `mode: only` — guardrail целиком на Jev: эвристики выключены (остаётся бесплатная проверка на пустой
  ответ). Легитимные правки, которые эвристики отклоняют («пиар» → «pull request»), начинают проходить.
  Минус: содержимое транскрипта может повлиять на ответ Jev (prompt injection), а сеть становится
  обязательной — при сбое работает `on_error`.
- `questions` — какие вопросы задавать и с каким порогом. Все вопросы уходят одним запросом и
  оцениваются параллельно: лишний вопрос стоит токенов (~$0.00004 за запрос), но не времени. Каждый
  ответ сводится к риску 0..1; один вопрос выше порога — чанк отклонён → повтор по предложениям →
  сырой текст, как и с эвристиками. Каталог вопросов — `QUESTIONS` в `s2t/jev.py`:
  точечные (`content_added`, `content_dropped`, `polarity_flipped`, `details_changed`, `roles_swapped`,
  `responded` — включены; `grammar_shifted`, `translated` — по желанию) и альтернативы одним вопросом:
  `meaning_changed` (Noul), `fidelity` (Score, шкала-допуск), `edit_kind` (Choice). На калибровочном
  наборе точечные вопросы разделяют хорошие и плохие пары с порогом 0.5, а все три альтернативы
  одним вопросом — нет (не видят пропавшее «только»), поэтому они не включены.
- `on_error` — Jev недоступен или не уложился в `timeout_s`: `heuristics` — решают эвристики
  (в `both` они уже пройдены), `reject` — остаётся сырой чанк.

Задержка: запрос уходит, пока LLM генерирует следующий чанк, а TLS-соединение открывается заранее,
во время STT. Замерено: вердикт приходит за ~310–420 мс по тёплому соединению; диктовка из одного
чанка ждёт его целиком (+0.4 с), из четырёх чанков — только последний (+0.3 с суммарно). Запрос
с шестью вопросами — ~1950 входных токенов ≈ $0.00008. `timings_ms.jev` — сколько вердикты реально
задержали результат (часть `cleanup`). `s2t transcribe -v` печатает вердикт по каждому чанку.
Если LLM не изменила ни одного слова (только пунктуацию и регистр) или чанк уже отклонили
эвристики, запроса к Jev нет — `jev_checks` в таком случае пустой.
В журнал пишется `jev_checks`: риски по каждому вопросу для **каждого** проверенного чанка, включая
принятые, — по ним и подбираются пороги.

## Словарь: три слоя

1. **Prompt для Whisper** — самый ценный слой: ошибка исправляется в источнике (лимит ~224 токена,
   поэтому в начало файла — самые важные термины).
2. **Глоссарий в системном промпте LLM** — справляется со словоформами («в докере» → «в Docker»).
   Полагаться только на него нельзя: маленькая модель может подставить термин из словаря вместо
   незнакомого слова — поэтому у слов из глоссария нет «пропуска» в guardrail.
3. **`aliases`** — жёсткая замена regex'ом: мгновенно, предсказуемо, без галлюцинаций. Нужны только
   для того, что первые два слоя стабильно не берут: имена, внутренние названия, устойчивые ослышки.

Обычно достаточно строки `- Kubernetes`; `aliases` добавляйте точечно, глядя на `raw_text` в выводе `-v`
или в журнале.

## Журнал (`history.jsonl`)

При диктовке виден только итоговый текст, поэтому каждый запрос дописывается строкой JSON в
`history.jsonl` (в корне репозитория, в `.gitignore`, права `0600` — **там всё надиктованное**):
`ts`, `origin` (`dictation` | `api` | `cli`), `file`, `requested_language`, все поля ответа
(`raw_text` — что услышал Whisper, `text` — что получилось, `timings_ms`, …) и `models`.
`cleanup_rejections` — каждое срабатывание guardrail'а: `reason` (`empty`, `too_long`,
`negation_gained`, `negation_lost`, `invented_words`, `dropped_words`, `jev`, `jev_error`), `words`
(какие именно слова; для `jev` — id сработавших вопросов),
`raw` / `llm` (чанк и отклонённый ответ модели), `fallback` (`true` — оставлен сырой текст,
`false` — чанк повторён по предложениям). `jev_checks` — каждый запрос к Jev: `raw`, `llm`, `risks`
(вопрос → риск 0..1), `failed`, `ms`, `tokens`, `model`, `error`. Записи «речь не найдена» тоже пишутся.

```bash
tail -n 5 history.jsonl | jq '{ts, raw_text, text, timings_ms}'
jq -c 'select(.cleanup_rejections != []) | .cleanup_rejections[]' history.jsonl   # что и почему отклонили guardrail'ы
jq -c '.jev_checks[]? | {risks, failed, ms, raw, llm}' history.jsonl               # оценки Jev — материал для порогов
jq -r 'select(.origin == "dictation") | .timings_ms.total' history.jsonl          # латентность живой диктовки
```

Настройки — секция `history` в `config.yaml`: `enabled`, `path`, `origins` (что журналировать).
Ротации нет: запись ~1 КБ. Аудио не сохраняется.

## Настройка

- `config.yaml` — все параметры (значения по умолчанию в `s2t/config.py`).
- `glossary.yaml` — словарь терминов.
- `dictation.keep_mic_open: true` — запись стартует мгновенно (иначе ~300 мс на открытие микрофона,
  сигнал «Tink» звучит, когда микрофон уже пишет), но индикатор микрофона macOS горит постоянно.
- `dictation.overlay` — индикатор записи: `enabled`, `position` (`top` | `bottom` | `top_left` |
  `top_right` | `bottom_left` | `bottom_right`, на экране под курсором мыши), `margin` (pt от края),
  `scale` (1.0 = высота 30 pt).
- Сравнить модели очистки: `uv run python scripts/eval_cleanup.py -v MODEL [MODEL ...]` —
  доля ответов, прошедших guardrails, и латентность на фиксированном наборе фраз.
- `cleanup.jev.enabled: true` — смысловая проверка результата моделью Jev (облако, нужен ключ);
  раздел «Смысловая проверка: Jev» выше, калибровка — `scripts/eval_jev.py`.
- Быстрее/легче: `cleanup.enabled: false` (Whisper сам ставит пунктуацию, пропадает только чистка паразитов).

### Справочник параметров `config.yaml`

Все ключи необязательны, значения по умолчанию — в `s2t/config.py`. Ключ верхнего уровня:
`glossary_path` (по умолчанию `glossary.yaml`) — путь к файлу словаря.

**`vad`** — Silero VAD (обрезка тишины, сегментация речи):

| ключ | по умолчанию | что делает |
|---|---|---|
| `enabled` | `true` | включить/выключить VAD (`false` — вся запись целиком идёт в Whisper) |
| `model_path` | `models/silero_vad.onnx` | путь к ONNX-модели; скачивается сюда сама при первом запуске |
| `threshold` | `0.5` | порог вероятности речи (0..1); «конец фразы» ловится на пороге ниже на 0.15 (гистерезис) |
| `min_speech_ms` | `150` | сегмент речи короче этого — шум (щелчки, нажатия клавиш), отбрасывается |
| `min_silence_ms` | `250` | тишина короче этого не разрывает фразу на сегменты |
| `edge_pad_ms` | `200` | сколько тишины оставлять по краям |
| `max_pause_ms` | `500` | паузы внутри речи длиннее этого сжимаются до этого значения |

**`stt`** — распознавание речи (Whisper):

| ключ | по умолчанию | что делает |
|---|---|---|
| `model` | `mlx-community/whisper-large-v3-turbo` | модель Whisper на MLX |
| `language` | `auto` | `auto` \| `ru` \| `en` — хоткей/запрос может переопределить |
| `auto_languages` | `[ru, en]` | `auto` выбирает язык только среди этих |
| `temperatures` | `[0.0, 0.2, 0.4]` | лесенка повторов: следующая температура пробуется, только если декод «выродился» |
| `no_speech_threshold` | `0.6` | выше — сегмент (при низкой logprob) считается тишиной, а не текстом |
| `compression_ratio_threshold` | `2.4` | сегмент сжимается (gzip) сильнее — похоже на зацикливание, декод неудачный |
| `logprob_threshold` | `-1.0` | средняя логарифмическая вероятность токенов сегмента ниже — декод неудачный |
| `max_prompt_chars` | `600` | сколько символов терминов глоссария (по порядку из файла) отдать Whisper как prompt |
| `hallucination_phrases` | 12 фраз | сегмент отбрасывается целиком, если начинается с одной из этих фраз (после нормализации); список — в `s2t/config.py` |

**`cleanup`** — LLM-очистка и guardrail'ы (описаны в таблице выше):

| ключ | по умолчанию | что делает |
|---|---|---|
| `enabled` | `true` | включить/выключить LLM-очистку |
| `model` | `mlx-community/Qwen3-4B-Instruct-2507-4bit` | модель очистки на MLX |
| `min_words` | `3` | текст короче стольки слов в LLM не отправляется |
| `chunk_chars` | `220` | длинный текст чистится кусками примерно такого размера (символов) |
| `max_dropped_ratio` | `0.1` | доля значимых слов, которую LLM может убрать; иначе — сырой текст |
| `max_negation_loss` | `0.5` | доля отрицаний, которую можно потерять |
| `max_length_ratio` | `1.3` | во сколько раз очищенный текст может быть длиннее исходного |
| `max_glossary_terms` | `150` | сколько терминов глоссария показывать LLM в системном промпте |
| `spelling_similarity` | `0.75` | порог схожести (difflib), чтобы слово засчиталось переспеллингом слова транскрипта |
| `translit_similarity` | `0.6` | то же после транслитерации кириллица↔латиница («питоне»→«Python») |
| `min_word_chars` | `3` | слова короче этого не проверяются guardrail'ами выдуманных/пропавших слов |
| `fillers` | 45 слов | слова, которые LLM может свободно удалять; список — `CleanupConfig.fillers` в `s2t/config.py` |
| `negations` | `[не, ни, нет, not, no, never]` | слова, которые считает guardrail `max_negation_loss` |

**`cleanup.jev`** — смысловая проверка моделью Jev (облачный API, описана выше):

| ключ | по умолчанию | что делает |
|---|---|---|
| `enabled` | `false` | включить проверку; тексты чанков уходят на `api.typesafe.ai` |
| `api_key_file` | `~/.config/s2t/typesafe_api_key` | файл с ключом; переменная `$TYPESAFE_API_KEY` имеет приоритет |
| `mode` | `both` | `both` — эвристики, затем Jev; `only` — Jev вместо эвристик |
| `model` | `jev-1.13.0` | версия модели, на которой откалиброваны пороги; новую сначала прогнать через `scripts/eval_jev.py` |
| `questions` | 6 вопросов по 0.5 | id вопроса из `QUESTIONS` в `s2t/jev.py` → максимальный допустимый риск 0..1 |
| `timeout_s` | `1.5` | дедлайн на вердикт, сек, от момента отправки; дальше — `on_error` |
| `on_error` | `heuristics` | Jev недоступен / не успел: `heuristics` — решают эвристики, `reject` — сырой чанк |

**`dictation`** — push-to-talk диктовка:

| ключ | по умолчанию | что делает |
|---|---|---|
| `enabled` | `true` | включить/выключить хоткей диктовки |
| `hotkeys` | см. выше | список `{key, language}` — клавиша (имя pynput) → язык |
| `min_record_ms` | `300` | клавиша зажата меньше этого — запись отбрасывается (случайное касание) |
| `max_record_s` | `300` | потолок длины записи, сек: наговоренное дольше обрезается перед распознаванием |
| `paste` | `true` | `false` — только положить текст в буфер обмена, без вставки |
| `restore_clipboard` | `true` | вернуть прежнее содержимое буфера обмена после вставки |
| `sounds` | `true` | звуковые сигналы начала/конца/пустой записи |
| `keep_mic_open` | `false` | см. выше — мгновенный старт записи ценой всегда горящего индикатора микрофона |
| `input_device` | `null` | `null` — устройство по умолчанию; число — индекс устройства; строка — подстрока имени устройства (регистронезависимо) |
| `overlay.enabled` / `.position` / `.margin` / `.scale` | см. выше | индикатор записи, описан в разделе «Диктовка» |

**`server`** — HTTP API:

| ключ | по умолчанию | что делает |
|---|---|---|
| `host` | `127.0.0.1` | адрес, на котором слушает API |
| `port` | `8765` | порт API |

**`history`** — журнал `history.jsonl` (описан ниже):

| ключ | по умолчанию | что делает |
|---|---|---|
| `enabled` | `true` | вести журнал |
| `path` | `history.jsonl` | путь к файлу журнала (относительный — от корня репозитория) |
| `origins` | `[dictation, api, cli]` | что журналировать: хоткей \| HTTP API \| `s2t transcribe --local` |

## Структура

```
s2t/audio.py     ffmpeg-декодер          s2t/cleanup.py   LLM-очистка + guardrail
s2t/vad.py       Silero VAD, паузы       s2t/pipeline.py  конвейер + Engine (один MLX-поток)
s2t/stt.py       Whisper MLX             s2t/server.py    FastAPI
s2t/glossary.py  словарь                 s2t/dictate.py   хоткей, запись, вставка
s2t/history.py   журнал history.jsonl    s2t/overlay.py   индикатор записи (отдельный процесс)
s2t/jev.py       смысловой guardrail (Jev, облако, опционально)
```

Бэкенд STT изолирован в `s2t/stt.py` (`load` / `transcribe`) — позже можно добавить
